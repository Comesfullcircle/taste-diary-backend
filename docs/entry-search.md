# 기록 검색 개발 기록

## 목적

제목과 카테고리로 원하는 기록을 찾을 수 있도록 기존 목록 API에 조건을 추가했다.

## 구현 범위

- 제목 부분 일치 검색, 영문 대소문자 구분 없음
- 카테고리 필터 및 두 조건 동시 적용
- 기존 날짜·ID 정렬과 페이지네이션 유지
- 검색 결과가 없으면 빈 목록 반환

## 선택한 방식

조건이 제목과 카테고리 두 가지여서 JPQL 쿼리 하나로 처리했다.
현재는 제목 전체에서 부분 문자열을 찾으며, 검색 전용 인덱스는 추가하지 않았다.
데이터가 많아져 성능 문제가 확인되면 실행 계획을 보고 개선할 예정이다.

검색어의 앞뒤 공백을 제거하고 `%`, `_`, `!`를 이스케이프했다.
사용자가 입력한 문자가 LIKE 패턴으로 해석되어 의도보다 많은 결과를 반환하지 않도록 했다.

## 테스트 중 발견한 문제

처음에는 검색어가 없으면 null을 전달하고 쿼리에서 조건을 생략하도록 했다.
PostgreSQL 통합 테스트에서 기본 목록과 카테고리 단독 조회가 실패했다.

```text
ERROR: function lower(bytea) does not exist
```

null 검색어를 LOWER에 전달하는 과정에서 문자열 대신 바이너리 타입으로 바인딩됐다.
검색어가 없으면 전체 제목에 일치하는 `%` 패턴을 전달하도록 수정했다.
제목은 필수 항목이므로 검색어 없는 전체 조회의 결과는 유지된다.

## 검증 항목

- 제목 부분 검색과 영문 대소문자 처리
- 카테고리 단독 및 검색 조건과 동시 적용
- 빈 검색어, 특수 문자, 결과 없는 검색
- 조건 적용 후 정렬과 페이지 이동
- 정의되지 않은 카테고리의 오류 응답
- 기존 CRUD 동작
